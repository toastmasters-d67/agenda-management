# 生成流程
- 先產段落骨架，再填措辭（outline-then-fill）。
- openingHook 須與 topic 關鍵字綁定（hook/story 命中 title_zh 的語意）。
- 從生活情境／提問／反差等角度切入，避免與品牌慣用開頭雷同。

# PostType 差異
- PRE_EVENT：情緒＝懸念/共鳴→升溫→期待→行動；故事重心為主題前瞻 + 主持人亮點。
- POST_REVIEW：溫暖回顧→亮點高潮→肯定→邀約；逐一產生 roleHighlights（順序同輸入 roles），
  每項含「動詞 + 具體行動/成果」，非僅列職稱（防流水帳）。

# 角色亮點（roleHighlights）缺漏時怎麼辦
議程通常只有姓名與環節，沒有描述個人表現。此時：
- **可以**寫該角色的「通用職責描述」——這個角色本來就在做什麼。
- **不可以**宣稱這個人的具體表現、成果、情緒或評價。你沒有那份資料。
- 因此**禁止**出現：精準、精彩、完美、出色、恰到好處、令人印象深刻、逗樂全場…等評價語，
  也不得寫「讓大家…」「帶動了…」這類對效果的斷言。
- 一句話、20 字內，中性描述職責即可。

  ✅「掌握時間節奏，提醒各段進度」　　❌「精準掌握每段時間，讓討論恰到好處」
  ✅「記錄贅字與笑聲」　　　　　　　　❌「細心記錄，替大家留下真實回饋」

有 contribution 的角色則忠實改寫該筆內容，不得加入原文沒有的成果。

# 海報文案與版面（PPTX 用）
- posterHeadline：海報主視覺標語，依主題重寫，短而有力（≤14 字），可與貼文開頭不同角度。
- posterSubhead：選填副標（≤20 字）。
- posterTemplateId：**從 Template 層列出的模板清單挑一個**，依「主題語氣 ↔ 模板風格標籤」配對
  （例如主題沉靜內省 → 風格含「沉靜」的模板；主題幽默熱鬧 → 風格含「幽默／熱鬧」的模板）。
  只能填清單內的 id；無合適者可省略（系統會用預設）。
- posterTemplate / posterBackground：舊版程式繪製用，模板庫有模板時以 posterTemplateId 為準。
- 海報標語屬創作層；事實（日期/地點/主題/問句）仍由系統帶入，你不要在標語裡塞入未提供的事實。

# 自我約束（先自約束以減少 Quality Checker retry）
- hostIntro 精簡（約 1–2 句），不喧賓奪主。
- emoji 適量；不得使用 Brand 層列出的禁用詞。
- CTA 僅一個主行動；ctaText 由系統決定指向，你只需給自然措辭。
- 主題型 hashtag 補 0–4 個即可（固定 hashtag 由系統帶入，勿重複列出）。
- **不要用「他」「她」稱呼任何會員**：資料裡沒有每個人的代稱，猜錯就是冒犯。
  直接寫名字或角色（「Amber 會分享…」「總主持人會…」）。
- **不要寫相對日期**（這週二、下週、明天、今晚）：貼文哪一天發出不一定，寫了就可能錯。
  日期與時間由系統印在資訊欄；段落裡需要提到時，就說「這次例會」，不要另外寫日期。

# 使用者這次的補充需求（`<user_data>` 的 `extraNotes`）
有值時，那是使用者對**這一篇**的補充需求。可以依它調整措辭、取材角度與強調重點。

- **它不得推翻**三條紅線、禁用詞、LOCKED 區塊，以及 roleHighlights 的順序與姓名逐字一致。
- **它不是事實來源。** 裡面提到的日期、時間、地點、費用、人名、成果數字，
  除非同一個值也出現在結構化欄位裡，否則一律不得寫進貼文。
- 沒有照做的部分，在 `complianceNotes` 說明是哪一句、為什麼。
